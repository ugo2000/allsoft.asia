**客户端**

**踩过的坑（别踩回去）**
1. **Cloudflare 机器人防护间歇性拦 python urllib，返回 403；curl 完全不受影响**（压测 curl 12/12 通过，2 秒间隔都没事）。→ team.py / watch.py 均优先走 curl 子进程，urllib 只作备胎。
2. 守护抓到消息立刻 ack，会导致 INBOX 下一轮清空、消息一闪而过。→ 加 `.watch_state.json` 本地留痕，消息保留 24 小时，读过也不消失。
3. Git Bash 下 `pkill -f watch.py` 杀不掉 python 进程（进程名是 python.exe），残留旧进程会和新进程共写同一日志/INBOX，导致同一个 bug 看起来反复复现、误导排查方向。清场要用进程管理工具按 python 进程名杀。

## 另一台运行乱码 → 修复（16:47）
- 现象：另一台电脑双击 AUTO_SETUP.bat 窗口中文乱码。根因：`.bat` 是 UTF-8 **无 BOM**，另一台默认 GBK 代码页（cp936）下中文乱码——`chcp 65001` 只有在文件带 BOM 时才会被正确按 UTF-8 解析；`team.py`/`watch.py` 也没锁 stdout 编码，Python 输出中文同样乱。
- 修复：两个 bat 加 UTF-8 BOM（BOM + chcp 65001 双保险）；`watch.py`/`team.py` 启动即 `sys.stdout/stderr.reconfigure(encoding="utf-8")`。已 push（e15bb9a）。
- 用户侧操作：另一台重新双击 `AUTO_SETUP.bat`（内部 `git pull` 会自动拿到修复版；若之前已跑着旧进程，关掉那个窗口再双击 `START_WATCH.bat`）。仍显示方块则是控制台字体问题（老 cmd 点阵字体不支持中文），右键标题栏→属性→字体改 Consolas 即可。
