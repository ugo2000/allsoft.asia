# 2026-08-21 工作日志

## pages.dev 子域名泄露流量 — 修复（pc-yotk）
- 现象：后台访客统计（`functions/api/track.js` 写 D1）频繁出现来源 `https://allsoft-asia.pages.dev/`。
- 根因：Cloudflare Pages 默认 `allsoft-asia.pages.dev` 子域名即使设了自定义域名 `allsoft.asia` 也一直公开可访问、内容同主站，被搜索引擎/爬虫收录并带来访客。
- 修复：新增 `functions/_middleware.js`，对 `host === allsoft-asia.pages.dev` 的请求 301 跳到 `https://allsoft.asia<path>`（分支预览地址不受影响）。
- 部署：`git push` 后用户给令牌，用 wrangler 部署成功（commit f332887）。
  - 本机部署要点：wrangler 在 `C:/Users/Administrator/.workbuddy/binaries/node/workspace/node_modules/wrangler/bin/wrangler.js`，node 在 `C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2/node.exe`；必须用 Windows 绝对路径（git bash 的 `/c/...` 会被 node 误解成相对 D: 的路径）；令牌以 `CLOUDFLARE_API_TOKEN=...` 传入（CF_API_TOKEN 已 deprecated 且不生效）。
  - 用户首次给的令牌 `cfat_...` 实测 API 返回 10000/1000 无效（疑似复制串字符）；第二次 `cfat_FcYj...` 经 `/user/tokens/verify` 报 1000 但 `/accounts/.../pages/projects/allsoft-asia` GET 返回真实数据，证明对 Pages 有效 → 部署成功。
- 线上验证：`allsoft-asia.pages.dev/` 与 `/blog` 均 301 → `allsoft.asia`；主站 200。
- 待办（可选，根治）：Cloudflare 后台 Workers & Pages → allsoft-asia → Settings → Domains 禁用 `allsoft-asia.pages.dev` 子域名，连爬虫都拿不到内容；当前 301 已覆盖真实访客。
